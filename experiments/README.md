# experiments/

Ten rounds of measurements on the truss optimisers in this repository, run between late
August and mid September 2026. Each round has a writeup. The writeups are the primary
artefact; the scripts and raw records exist so that every number in them can be
regenerated.

The experiments were run, and these writeups drafted, with Claude Code (Anthropic) under
Oliver Fan's direction; Oliver reviewed the results and is responsible for the claims. The
first person in the writeups is that working session, not a lab member.

Nothing in this folder is imported by `main.py`. The optimiser code lives in
`../optimization/`; the changes made to it during these rounds are listed at the bottom.

## Layout

| path | what |
|---|---|
| `RESULTS*.md`, `PLAN_ROUND6.md` | the writeups, one per round (rounds 7–9 share one) |
| `*.py` | runners (`runnerN.py`, sharded batch jobs), one-off experiments (`exp_*.py`), analysis (`analyze*.py`), and the parameterised model copies the early rounds trained (`variant.py`, `repair_variant.py`) |
| `max_values.npy` | the hypervolume reference every round except 6 is scored on. Byte-identical to `max_values_random16k.npy`, the lab's original 16,000-sample random-search reference |
| `max_values_rebuilt_round6.npy` | the reference round 6 rebuilt (frequency axis 0.879 to 1.75) and later reverted. Only `RESULTS_ROUND6.md` is on it |
| `data/` | raw per-run records (`*_shard_*.jsonl`), probe outputs (`*.json`), the round-9 supervised pointer checkpoint, and round 6's observed bounds. Committed |
| `logs/` | stdout/stderr of the shard launches. Not committed |
| `r*work/` | trained checkpoints and training plots (about 130 MB of `.pth`). Not committed; regenerated by the runner that names them |

## Read in this order

Later rounds overturn earlier ones, and each writeup says so where it happens. The
one-line summaries below are each writeup's own headline, not a synthesis.

| round | writeup | headline |
|---|---|---|
| 1 | `RESULTS.md` | None of five proposed policy/training changes improves hypervolume. Two implementation bugs found: positional encoding indexed by batch instead of by position, and a PPO importance ratio that is not 1 at the first update. Seed-to-seed variance is too large for 6-run comparisons. |
| 2 | `RESULTS_ROUND2.md` | At n=8, the hybrid GA's gain comes from the operator's structure, not from training (overturned in round 4, then re-explained in round 5). Warm Start GA is a null result. |
| 3 | `RESULTS_ROUND3.md` | A hypervolume-improvement reward against a batch-local archive lifts the synthesis PPO by 30% with 5x less variance. Round 2's "bug fixes lower HV" was a harness bug. Goal-conditioned PPO added: it works and loses. |
| 4 | `RESULTS_ROUND4.md` | First equal-budget comparison of the two families: the hybrid wins. A trained repair operator beats an untrained one once the rollout/update observation mismatch in `design_repair.py` is fixed. Resetting the archive every 5 epochs beats every epoch. |
| 5 | `RESULTS_ROUND5.md` | The hybrid's advantage is its mutation rate (1 bar vs 8), not its network: the trained pointer head is exactly uniform. `max_values.npy` is 80% low on frequency and hypervolume was unclipped, so scores above 1.0 were routine. Elitism is the biggest single lever. |
| 6 | `PLAN_ROUND6.md`, `RESULTS_ROUND6.md` | Metric rebuilt, GA tuned (elitism 8, 1-bar mutation, tournament selection; confirmed on held-out seeds), every method re-baselined. The rebuilt reference was reverted afterwards, so these numbers are not comparable to any other round. |
| 7–9 | `RESULTS_ROUND7-9.md` | Giving the operator the physics (a stress channel) and a length-neutral reward does not help at deployment. No fixed physics rule beats blind mutation, and a supervised pointer that genuinely learns bar selection still loses as an operator. Posing the truss with its 16 symmetry groups helps every method. Random search normalises against its own sample (`random_search.py:48`). |
| 10 | `RESULTS_ROUND10.md` | Revises round 9's "ceiling": an operator aimed at hypervolume gain directly beats blind mutation when its lookahead is free, and loses when charged. A single-bar edit is a rank-1 stiffness update, so that oracle is closed-form on the truss. |

## Running

- Run from the repository root, for example `python experiments/runner23.py --shard 0 --nshards 6`.
  Every script locates the repo and its own data relative to its file, so the working
  directory does not matter.
- Needs the repo's dependencies plus `pygad` and `pymoo`. Round 1's scripts assume a GPU.
- Runners are sharded and resumable: they skip `job_id`s already present in their output
  shard, so `--nshards` can change between launches. Logs are whatever stdout is
  redirected to.
- Set `OMP_NUM_THREADS=1` when running several shards at once, or each torch process
  claims every core.
- The synthesis PPO is faster on the GPU; the repair PPO and the GAs are faster on the
  CPU, because they roll out one design at a time. See the hardware note in
  `RESULTS_ROUND4.md`.

## Changes made to the main codebase

Every change is behind a `params` key whose default reproduces the earlier behaviour,
except where a writeup records a deliberate default change (marked **default changed**).

| file | change | round |
|---|---|---|
| `evaluation/truss_problem.py` | Vectorised assembly and solve (geometry precomputed once, `bincount` scatter, dense `solve`); same objectives. `evaluate(..., return_utilisation=True)` returns the per-bar utilisation the solver already computes. A singular structure returns a penalised result instead of raising. | 5, 7 |
| `utils/hypervolume_utils.py` | `track_pareto_progress`: one incremental, linear-time front tracker replacing the per-method copies, which were quadratic and let an infeasible first design seed the front. It clips negative normalised coordinates, which otherwise integrate volume outside the unit cube. `RunningParetoArchive` backs the hv reward. | 3, 5, 6 |
| every `optimization/*.py` | Uses `track_pareto_progress` instead of its own copy of the loop. | 3 |
| `genetic_algorithm.py` | **default changed**: `mutation_num_genes=1`, `keep_elitism=8`, tournament selection with `K_tournament=3` (was 10% mutation, no elitism, `sss`). All overridable via `params`. `nfe_budget` stops on evaluations rather than generations. | 5, 6, 9 |
| `intelligent_mutation_ga.py` | Same GA knobs via `params`, defaults left at the historical values. `random_init_actor` (ablation), `use_stress`, `max_edits`, `nfe_budget`. | 2, 7, 9 |
| `warm_start_ga.py` | **default changed** to match the GA (`mutation_num_genes=1`, `keep_elitism=8`); the elitism value is extrapolated, not measured, and the file says so. `random_init_actor`. | 2, 6 |
| `warm_start_intelligent_ga.py` | `random_init_actor`. | 2 |
| `design_repair.py` | `obs_mode` (**default changed** to `'design'`): the PPO update now sees the same 72-token state the policy acted in and the hybrid GA deploys it on; `'full'` reproduces the old mismatch. `use_stress`, `reward_shape='potential'` (length-neutral shaping), `max_edits`. | 4, 7 |
| `transformer_design_repair.py` | The Critic's positional encoding was indexed by batch; fixed. Optional second input channel (utilisation) with input normalisation; `pointer_entropy_coef`. | 5, 7, 8 |
| `transformer_rand_weights_state.py` | Positional encoding fix in Actor and Critic. `ppo_update(..., action_pos)` scores each action at the slot it was taken at instead of the padded last slot. **default changed**: dropout 0 (was 0.1) and fp16 autocast off (`use_amp`); both made the importance ratio differ from 1.0 at the first update. | 1, 3 |
| `transformer_rand_weights_uninformed.py` | Positional encoding fix; dropout default 0. | 1 |
| `ppo_rand_weights_state.py` | `reward_mode` (`'scalarized'`, the original, or `'hv'`), `hv_reset_period`, `hv_scale`, `infeasible_penalty`, `pin_constraint_weights`; passes action positions to the update. | 3, 4, 9 |
| `ppo_goal_conditioned.py` | New method (round 3). Listed in `main.py` but commented out: it works and loses to the hv reward. | 3 |
| `main.py` | `param_overrides` per method (used for the ablation arms, listed commented out). The hypervolume plot draws every run faintly behind the median and puts n in the legend. **default changed**: `reward_mode='hv'`, `hv_reset_period=3`, `hv_scale=200`, `obs_mode='design'`. Set `reward_mode='scalarized'` and `obs_mode='full'` to reproduce the original methods exactly. | 2, 4, 5 |

### Deliberately left alone

- `max_values.npy` in the lab's results folders, and `random_search.py:48`, which builds
  the reference from its own sample. Both are measurement decisions that would change
  every number the lab has reported (`RESULTS_ROUND7-9.md`, *Questions for the lab*).
- The hybrid methods' historical GA settings (elitism 0, `sss`), so that the arms measured
  in rounds 1–6 are still the arms the code produces by default.
